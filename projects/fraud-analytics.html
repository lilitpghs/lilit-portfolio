Fraud Detection & Transaction Risk Analytics

Investigating transaction patterns and comparing fraud detection approaches to understand how suspicious activity can be prioritised when investigation capacity is limited.

The challenge

Fraud teams operate under limited investigation capacity. Reviewing every transaction is impractical, while overly broad alerts can create substantial work for analysts. The challenge is to identify suspicious transactions effectively without relying on a single indicator such as transaction amount.

This project investigates whether a statistical model can prioritise labelled fraud cases more effectively than a simple rule that flags the highest-value transactions.

My approach

  • Inspected the transaction dataset, class distribution, missing values and duplicate records.
  • Explored transaction amount patterns and compared fraud rates across amount segments.
  • Developed a logistic regression model using a stratified training, validation and test split.
  • Selected a probability threshold using validation data to target a limited review queue.
  • Evaluated model performance using recall, precision and other classification metrics.
  • Compared the model with a highest-amount rule at the same review capacity on held-out test data.

Key finding

At an equal review capacity of approximately 2% of test transactions, logistic regression detected 90 labelled fraud cases, compared with 2 detected by a highest-amount rule. This illustrates the potential value of considering multiple transaction signals rather than transaction amount alone.

The model achieved 90.91% recall on the held-out test set at the validation-selected threshold. Recall measures the proportion of labelled fraud cases identified by the model; it does not measure financial losses prevented.

Model vs. simple rule

Both approaches were compared at the same review capacity: 1,140 flagged transactions in the held-out test set.

Results are from an offline evaluation on a held-out test set. Precision indicates the proportion of flagged transactions that were labelled fraud. Most model alerts were not labelled fraud, highlighting the continuing need for effective review processes.

Business implications

  • Look beyond transaction value. A high-value-only rule may miss fraud occurring in lower-value transactions.
  • Optimise for review capacity. Measure how many cases are detected alongside the number of alerts requiring investigation.
  • Keep analysts in the loop. False positives remain substantial, so model alerts should support investigation rather than automatically establish fraud.
  • Validate before deployment. Test on future transactions and assess operational costs before using the approach in a live environment.

Limitations

  • The evaluation uses a random stratified split rather than a time-based test of future transactions.
  • The anonymised V1–V28 features limit direct interpretation of individual transaction signals.
  • Fraud labels do not establish actual financial losses or recovered amounts.
  • Offline model results do not demonstrate real-world savings or fraud prevention.
